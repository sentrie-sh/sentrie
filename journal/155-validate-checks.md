### 2026-11-10 23:10 - Implement the self-reference and identifier checks
- Re-reproduced on the base (308-shape-with-resolver, 9869173) with a scratch pack: `rule r = r` and `yield undefined_thing` both passed `sentrie validate`. Unknown shape and type names (`let x: Nope = 1`, `let x: bool = true`) did NOT reproduce: `checkShapeRefs` (#282) already rejects them with `shape 'Nope' not found`. No work there.
- Self-reference: did not simply propagate `AddEdge`'s `ErrSelfLoop` in `addNodes`. The identifier graph ignores scope, so `rule x = { let x = 1 yield x }`, a lambda parameter named like the rule, or a block `let user = user.name` over a fact `user` would all be false self-loops. New `index/self_reference.go` (`detectSelfReference`) resolves each identifier in `evalIdent`'s order (enclosing lambda params, data, facts, nearest let, rule) and reports one that resolves to the rule or let whose value it is in. The `addNodes` self edge stays dropped, with a comment pointing at the new check. Runs right after `detectReferenceCycle`.
- Fail-safe choices in the self-reference check (journaled per the decision): no owner inside a lambda body (misses `filter(xs, (x) => { yield r })`, which still fails at runtime); callees skipped; a name declared twice in one block is never reported (see example_pack below); contributions left to `detectContributionSelfReference`; derive bodies not walked.
- Undefined identifiers: new `index/ident_check.go` (`checkIdentifiers`) over `forEachScopedExpr` with `namesValue`, so it covers every site the other static checks do (fact defaults, lets, rule slots, contributions, attachments, import `with` values). Callee subtrees are skipped (getTarget never evaluates a callee); derive bodies are skipped (derive purity already rejects unknown names there). Hints for a `use` alias, a name imported from a module, and a builtin used as a value. Runs after the self-reference check.
- Found while checking scopes: the runtime scopes rules and lets dynamically. `evalIdent` evaluates a let or rule in the referencing context, so `let y = x + 1` read inside `(x) => { yield y }` reads the parameter, and a block let leaks into a rule read from inside the block (verified with `exec` on the base: both evaluate). A lexical check would reject packs that run, so every name bound by a lambda parameter or block let anywhere in the same policy is never reported. Imports (fresh root context) and derives (detached) do not leak. Candidate issue below.
- Fact defaults run before lets are bound, so a fact default reading a let fails at runtime; the let is defined, so it is not reported (fail safe).
- `cmd/validate.go`: removed the `rule` argument and `--facts` flag, added a description and long help. cling binds positionals silently, so `validateCmd` rejects any non-flag word (`validate takes no arguments, got "t/p"`). PROVISIONAL (user AFK), needs confirmation: rejecting a stray positional rather than ignoring it, so old `sentrie validate t/p` invocations now fail.

### 2026-11-12 10:39 - Review comment: shadowed let self-reference
- Review comment (repo owner, `index/self_reference.go:139`): the resolver treats the nearest let as the binding, but `evalIdent` checks `GetLocal` across ancestor contexts before `GetLet`, so `let x = 1` with `rule r = (x + { let x = x + 1 yield x }) == 2` runs as `true` on base 9869173 and this branch rejected it with `let 'x' references itself`. Reproduced both: branch validate and exec fail, base exec gives `true`.
- What a cached local can hold (runtime/exec_ctx.go `SetLocal`): an evaluated let or rule, cached in the context that declares the let, or any context for a rule name; lambda parameters. Facts are not locals but are read before lets, so they already resolved first.
- Decision (orchestrator, conservative, consistent with the dynamic-scope treatment): do not model runtime caching. A let reading its own name is skipped when an enclosing block let, a policy let or a rule binds the same name (`outerBinding`); fact and lambda parameter shadowing already won in `resolve`. Unchanged: `let x = x + 1` with no outer `x`, `rule r = r`, the attachment case. Known gap, noted in the graph node and PR Review notes: `rule r = { let x = 1 yield { let x = x + 1 yield x } }` is now skipped though it fails at runtime on base (outer `x` never read first).
